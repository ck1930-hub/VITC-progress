# Financial AI Command Center — Frontend

## Overview

The frontend is the visual and interactive layer of the Financial AI Command Center.

It transforms financial data, risk analysis, simulations, and recommendations generated by the backend into an interactive financial decision-support dashboard.

Rather than functioning as a traditional banking interface that only displays balances and transactions, the application is designed to help users understand:

- Their current financial position
- Financial health and stability
- Cash flow
- Financial risks
- The impact of unexpected events
- Possible future scenarios
- Alternative financial decisions
- Recommended actions and associated trade-offs

The frontend follows the following data flow:

```text
User Opens Dashboard
        │
        ▼
Next.js Application Loads
        │
        ▼
API Service Requests Financial Data
        │
        ├──────────────► GET /state
        │
        ├──────────────► GET /risks
        │
        ├──────────────► GET /simulation
        │
        └──────────────► GET /recommendation

                              ▼

                              │
                              ▼

                              │

                     Frontend State Update
                              │
                              ▼
                   Dashboard Visualizations
```

# Dashboard Sections

## 1. Financial Health

Provides a high-level assessment of the user's financial position.

The dashboard visualizes:

- Overall financial health score
- Liquidity
- Income certainty
- Obligation safety
- Emergency buffer

---

## 2. Financial Snapshot

Displays the most important financial information in a compact format.

Examples include:

- Confirmed balance
- Expected income
- Upcoming obligations
- Emergency reserves

---

## 3. Financial Digital Twin

Provides a visual representation of the user's current financial state.

The purpose is to allow the user to understand the relationship between available funds, expected income, obligations, and financial risk.

---

## 4. Cash Flow Analysis

Visualizes the movement of money through the financial system.

```text
Income
   │
   ▼
Available Funds
   │
   ├── Rent
   ├── EMI
   ├── Insurance
   ├── Investments
   │
   ▼
Remaining Liquidity
```

---

## 5. Event Simulation

Allows financial disruptions to be simulated interactively.

The current prototype supports:

```text
PAYMENT_DELAYED
```

After the event is triggered, the dashboard updates to reflect:

- Changes in income certainty
- Updated financial risk
- Projected financial outcomes
- Alternative decisions
- Recommended intervention

---

## 6. 30-Day Projection

Displays multiple possible future financial scenarios.

```text
Financial Position

        │
        │                         Optimistic
        │                       /
Balance │                 Expected
        │                 /
        │          Pessimistic
        │
        └─────────────────────────────────
             Day 1                 Day 30
```

The projections help communicate uncertainty instead of presenting a single assumed future.

---

## 7. Risk Analysis

Displays financial risks identified by the backend.

The current interface supports visualization of:

- Liquidity risk
- Income certainty risk
- Obligation risk
- Emergency buffer risk

---

## 8. Decision Lab

The Decision Lab presents alternative actions generated by the backend.

Current alternatives include:

```text
DO_NOTHING

PAUSE_SIP

REDUCE_DISCRETIONARY_SPENDING
```

Each alternative can be compared based on its potential financial consequences.

---

## 9. Recommendation Panel

Displays the final structured recommendation generated by the backend.

The recommendation can include:

- Recommended action
- Supporting reasoning
- Confidence
- Identified risks
- Alternative actions
- Trade-offs

# API Configuration

The frontend communicates with the backend through an environment variable.

Create a `.env.local` file:

```env
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8765
```

For a backend running on another device within the same network:

```env
NEXT_PUBLIC_API_BASE_URL=http://<BACKEND_DEVICE_IP>:8765
```

Example:

```env
NEXT_PUBLIC_API_BASE_URL=http://172.16.45.251:8765
```

Restart the Next.js development server after modifying `.env.local`.

---

# API Integration

The frontend API layer is located at:

```text
src/services/api.ts
```

The API client communicates with the following backend endpoints:

```text
GET  /state

GET  /events

POST /simulate/PAYMENT_DELAYED

GET  /simulation

POST /simulation/reset

GET  /risks

GET  /recommendation
```

The frontend uses:

```text
NEXT_PUBLIC_API_BASE_URL
```

as the backend base URL.

# Running the Frontend

## Prerequisites

Install:

- Node.js
- npm

---

## 1. Navigate to the Frontend Directory

```bash
cd frontend
```

---

## 2. Install Dependencies

```bash
npm install
```

---

## 3. Configure the Backend

Create `.env.local`:

```env
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8765
```

Ensure the backend is running before starting the frontend.

---

## 4. Start the Development Server

```bash
npm run dev
```

Next.js will display a local URL similar to:

```text
http://localhost:3000
```

If port `3000` is already occupied, Next.js may automatically use another port, such as:

```text
http://localhost:3001
```

# Production Build

To verify that the frontend builds successfully:

```bash
npm run build
```

To run the production build:

```bash
npm start
```

# Error Handling

If the backend is unavailable, the frontend displays an application state indicating that the backend connection could not be established.

This prevents the dashboard from presenting unavailable backend data as live information.

Common issues include:

```text
Incorrect NEXT_PUBLIC_API_BASE_URL
```

```text
Backend server not running
```

```text
Incorrect backend port
```

```text
Firewall blocking the backend port
```

```text
Frontend and backend devices not connected to the same network
```

# Design Philosophy

The interface is designed around the principle that financial information should support decision-making rather than simply display data.

The user journey follows:

```text
Understand Current State
          │
          ▼
Identify Financial Risk
          │
          ▼
Simulate a Financial Event
          │
          ▼
Observe Future Scenarios
          │
          ▼
Compare Possible Actions
          │
          ▼
Understand Trade-offs
          │
          ▼
Receive a Structured Recommendation
```

# Relationship with the Backend

The frontend is responsible for presentation and interaction.

```text
FRONTEND RESPONSIBILITIES

User Interface
Visualizations
Graphs
Scores
Interactions
Simulation Controls
Decision Comparison
Recommendation Display
        │
        │ REST API
        ▼
BACKEND RESPONSIBILITIES

Financial State
Event Processing
Simulation Logic
Risk Analysis
Scenario Generation
Alternative Evaluation
Recommendation Generation
```

This separation keeps the financial decision logic independent from the user interface.
